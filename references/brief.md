# The brief: defaults to take, facts to get

Do not interview the user. Read the product's repo and docs, apply these defaults, and state what you assumed in the first message of the work.

## Facts to extract from the product (and write into SPEC.md)

1. **The lifecycle:** the ordered stages a person meets (e.g. Discover → Scan → Report → Remediate → Export), what each produces, and any step the user later says they forgot (ask yourself: where do results get reported? how do new inputs arrive over time?). Phases beside the lifecycle (a toolbox) are a separate act.
2. **Tagline:** one line, official and specific. Offer 5–8 options in different registers if none exists; the user chooses; never keep a placeholder.
3. **What is shipped and what is not.** Read the code and docs, not the roadmap. Anything on the roadmap is shown only as "keeps growing" and listed at the end.
4. **Real mechanisms, in plain words:** what the engine actually does (a vision model reads the rendered page; a speech-to-text model writes words with timestamps; content fingerprints find unique files and changes).
5. **Placeholder numbers:** invent consistent, arbitrary-looking figures; list them.
6. **A neutral sample document** to run through the real engine for the demo frames (never a real, sensitive one).

## Defaults

| Choice | Default |
|---|---|
| Format | 1920×1080, 30 fps authoring, delivered at 60 fps |
| Length | as long as the story needs (the example is 3.5 minutes); never pad |
| Voice | Kokoro `af_heart`, plain take, one continuous track |
| Style | this skill's taste (light paper, Manrope, per-stage accents, clean marks) |
| Opening | the name animation, then the tagline spoken once |
| Closing | night ground, tiles lit by the product's light, silent lockup |
| Sound | bed + sound design, voice dominant |
| Captions | always; switchable; sidecar files |
| Delivery | master + share copy + player |
| Git | do not commit or push unless asked |

## What to ask only if you cannot find it

- The product's name and how it is written (case, the one lit letter).
- The tagline, if the user wants a say (offer options).
- Whether the product's own launch screen should reuse the film's name animation (the example keeps the app's launch screen simple and the film's animation long).
