# Pipeline, review loop, export, pitfalls

## Project layout

```
film/                       a HyperFrames project (npx hyperframes init film --skip-skills)
  index.html                generated by scripts/build_index.py
  scenes.json               [{id, key, src}] in paint order (the rail last)
  timing.json               generated by scripts/retime.py: scenes {key: [start, duration]}, voice {id: start}, total
  script.json  layout.json  score.json  sfx-cues.json
  compositions/             one file per scene
  assets/lib/motion.js      from templates/lib/ (LM helpers)
  assets/fonts/             Manrope from templates/fonts/
  assets/voice/             clips cache, voice.json, narration.wav, bed.wav, sfx.wav
final/                      exports and captions (next to film/)
SPEC.md                     the film's plan: structure with seconds, narration table, accent system, open claims
```

## The loop

1. `retime.py` → `build_index.py` → `check` → `snapshot`.
2. `check --json > /dev/null` then `scripts/check_report.py .` (the JSON on stdout can be truncated; the saved report is complete). Errors must be 0. Warnings: weigh each. Expect and accept: `line_unread` on rolling digits, `svg_round_cap_hidden_dash` on check marks, a handful of `text_below_floor` on badges that scale up from small; fix everything else.
3. `snapshot --at t1,t2,…` produces PNGs and a contact sheet. Read them. Pick times: every scene boundary (before, during, after), the moment each new element lands, each number's final value, the longest line, the last frame.
4. For a defect a viewer reports "at 3:10": `snapshot --at 190`, find it, fix it, check the neighbouring seconds.
5. Only when frames are clean: `export.sh`.

## The creative director's pass

The creative director is a standing role with this skill's taste (see [taste.md](taste.md)), not a one-off step: every phase and section is looked at through it (storyline, script, each scene, sound, captions, export). The full pass below is run **twice** before a film is called done: once on the first complete build, and again on the result of fixing it, over every scene and the audio sheet. Review the contact sheets as an art director would, scene by scene, and write the defects before fixing them.

- **Hierarchy and focus:** one focal object per scene; is anything competing? Is there dead space for more than ~3 s that a larger object, a centred start or an arriving second object would fix?
- **Type:** nothing under 28 px; nothing clipped, wrapped badly or leaving the canvas; chips never touching a name; numbers aligned when settled.
- **Colour:** each stage and tool in its own accent; amber only on the light; no more than one saturated colour per object; status colours consistent.
- **Marks:** a mix of highlight / line / both / outline; none repeated twice in a row; no wobble.
- **Motion:** every arrival has a matching exit; transitions overlap 0.4 s; no object pops; paths are smooth; nothing moves "off" (a rotating icon turns about its own centre; a card does not rise into the rail).
- **Collisions:** persistent rail vs content; lockup vs tiles; labels vs lines; layers vs titles.
- **Sync:** the visual beat is on the phrase that names it (check with `silencedetect`), not a second early.
- **Story:** does every scene earn its time; does the closing avoid repeating the opening; is any claim larger than the product?
- **Numbers:** arbitrary-looking placeholders, consistent across scenes (the funnel's numbers match the master report's).

Fix, re-snapshot, repeat until a pass finds nothing worth fixing. Then say honestly what you did not check (audio by ear, motion watched live).

## Export

`scripts/export.sh <film-dir> <name> <captions-basename>`:

- master: `hyperframes render --quality delivery --fps 60` (1080p, h264, aac),
- share copy: x264 CRF 22, slow preset, much smaller,
- both with the captions embedded as a switchable `mov_text` track (off by default, language `eng`), plus `.srt` and `.vtt` sidecar files and `player.html` (a `<video>` with a `<track>` and a CC button).

Tell the user the sizes; if an upload channel limits file size, send the share copy and say where the master is. Re-render **and re-attach captions** after every visual fix (timing unchanged means the same captions file is valid).

## Pitfalls

| Symptom | Cause | Fix |
|---|---|---|
| `check` error "layout property tween" | tweening `left/top/width/fontSize` | tween `x/y/scale`; morph one element into another by crossfading two elements |
| An element invisible after `scaleX(0)` in CSS | singular matrix GSAP cannot read | set transforms through GSAP (`fromTo scaleX`) |
| A stroke or ring visible at t = 0 | `fromTo` applies its from-values immediately | `tl.set(el, {opacity: x}, t)` then `tl.to(...)` |
| Text/state not updating in render | callbacks and `className` changes are suppressed when seeking | derive text/state in `paint()` driven by one linear tween of the whole scene |
| Round-cap dot before a stroke draws | zero-length dash with round cap | hide with opacity until the draw starts, or use HTML elements revealed by clip/scale |
| Overlapping tween warning | two tweens on one property overlap | make them sequential or merge |
| A number settles misaligned | odometer carry formula uses lower digits' fractions | `LM.odometer` carries only in the last unit before a wrap |
| Contrast warning on white digits | sampled while the pill behind is still fading in | fade the digits in after the pill is opaque |
| Animation frozen in the preview pane | the browser pane is hidden | show the pane (preview) before judging motion |
| `ReferenceError` in one scene only | a helper constant (e.g. `NS`) removed from `motion.js` while another helper uses it | grep for every identifier a helper uses before deleting |
| A host element scaled by CSS fights GSAP | CSS transform on a GSAP-animated element | animate the scale in GSAP on the host, not in CSS |
| Odd fractions on rolling digits | leading digits shown as zeros | hide leading zeros and stray commas (`LM.odometer` does) |

## Adding or changing scenes in a finished film

- **Keep earlier scenes where they are.** Their beats are written against their own timing; a longer take anywhere else would move every scene after it. Give each unchanged scene its old `start`, `duration` and absolute line times in `layout.json`, let only the new scenes flow, and shift the scenes after them by the length that was added. Retime, then compare every old scene's start and duration with the old `timing.json` before going on.
- **Keep the voice takes you already have.** `narrate.py` caches a take by text and target; if its cache key changes (a rebuilt tool, a new voice setting) every line is voiced again and every length drifts. Before re-voicing, copy the old take over the new key for each unchanged line and check that `voice.json` still shows the old lengths.
- **Write a new scene's beats from the voice, not by guess:** put a `/*TIMING*/` block in it and run `scripts/fit_timing.py` after every retime; place the visual beat on the phrase that names it (`silencedetect` on the narration gives each phrase's start).
- A scene that has no shared element with its neighbour leaves as one blurred sheet and the next one arrives with its own entrance; do not rely on a previous scene's leftover object.
